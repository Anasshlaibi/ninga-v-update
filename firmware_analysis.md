## 2. Outer container — VERIFIED
- **Global header (16 bytes):** size 16, magic bytes `wfsa`, version `0x01000000`, 8 sections.
- **Section layout:** a 24-byte header (`<I4sIIII>`: total_len, magic, version, id, payload_len, checksum), then the payload, then a 4-byte trailer, so `total_len = payload_len + 28`.
- **Magic strings are stored byte-reversed:** `nib ` = bin, `nibx` = xbin, `xdi ` = idx.

| # | Header offset | Type | ID | Payload bytes | Content |
|---|---|---|---|---:|---|
| 0 | `0x00000010` | bin | `0xaaaaaaaa` | 1,024 | all zero |
| 1 | `0x0000042c` | bin | `0xaaaaaaab` | 1,024 | all zero |
| 2 | `0x00000848` | bin | `0xaaaaaaa2` | 1,024 | all zero |
| 3 | `0x00000c64` | xbin | `0x11111111` | 294,387,712 | gzip → FAT16 image (355,729,408 B, 40 files) |
| 4 | `0x118c0c80` | xbin | `0x31323334` | 2,097,152 | Xilinx boot image (primary) |

## 3. Xilinx boot images — VERIFIED header fields
Both QSPI images (sections 4 and 5), `APP0000.BIN`, `DAPP0000.BIN` and all 15 `DPGA*.BIN` files share the same structure: the `XLNX` magic at offset 0x24, an image header table and partition headers. Raw fields for each partition are in `phase1_evidence.json` → `boot_images`.

### 3.3 Protection status — VERIFIED observation, INFERRED meaning
Two partition groups behave differently:

**Group A — looks encrypted:** FSBL, PMU firmware, BL31, `phoenix_boot.bin`, every `startrek_noresources.elf` partition and every `.bit` partition. They show:
- entropy ≥ 7.99;
- no ELF magic and no FPGA sync word;
- `enc_len` larger than `unenc_len`;
- a non-zero boot-header key-source word (`0xa5c3c5a3` in most files, `0xa3a5c3c5` in `APP0000.BIN`).

**Group B — plaintext:** `boot.dtb`, `u-boot.elf` and `startrek.resource_pack.p32`. Here `enc_len` equals `unenc_len`, and the content is readable.

INFERRED: Group A is encrypted with a device-held key, so its contents cannot be analysed statically. The project treats these components as **opaque black boxes**. We will not attempt to decrypt, bypass or replace them. Any custom work must stay within the readable Linux side or use external hardware.
