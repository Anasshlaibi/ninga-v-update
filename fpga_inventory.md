# Phase 1 Deliverable: FPGA & Programmable Logic Inventory (`ATOMNJV.FW` — AtomOS 11.19.00)

- **Project:** Verdanove Ninja Lab
- **Target Device:** Original Atomos Ninja V (5-inch model)
- **Firmware Baseline:** AtomOS `11.19.00` (`ATOMNJV.FW`)

---

## 1. Multi-FPGA Architecture Summary

Static analysis of `ATOMNJV.FW` proved that the Ninja V ecosystem contains **three distinct classes of FPGA bitstreams** across the main unit and its AtomX expansion modules:

1. **Primary SoC Programmable Logic (Xilinx Zynq UltraScale+ `XCZU5EV` PL):**
   - **15 main bitstreams (`DPGA0000.BIN`–`DPGA0020.BIN`) + 2 aliases (`XMODSDIN.BIN`, `XMODSYNN.BIN`) + 1 recovery bitstream (`emergency.bit` in `sec5`)**.
   - Packaged as Xilinx ZynqMP `BOOT.BIN` partition containers (`XLNX` header, Key Source `0xA5C3C5A3` = `EFUSE_RED_KEY`, Partition Attribute `0x80` = Encrypted, Destination Device = PL).
   - Dynamically swapped at runtime by `/etc/init.d/load_fpga.sh` via the ZynqMP CSU/FPGA Manager (`/sys/class/fpga_manager/fpga0/firmware`), depending on the active codec (ProRes, DNxHR, ProRes RAW, H.265, CAST, or Streaming).
2. **AtomX Expansion Module Xilinx Artix-7 FPGAs (`FMODDOCK.BIN`, `FMODSTRM.BIN`, `XMODDOCK.BIN`, `XMODSTRM.BIN`):**
   - **Completely unencrypted** Xilinx 7-Series bitstreams (`.bit` and JTAG `.svf`) built with Vivado `2021.1` for the **AtomX CAST (`7a35tfgg484`)** and **Atomos Connect (`7a25tcsg325`)** expansion accessories.
3. **AtomX Expansion Module Intel MAX 10 FPGAs (`XMODSDI.BIN`, `XMODSYN.BIN`):**
   - **Unencrypted** ASCII JTAG Serial Vector Format (`.svf`) files generated by **Intel Quartus Prime 18.0** targeting the **Intel MAX 10 `10M04SC`** CPLD/FPGA used on the **AtomX SDI** and **AtomX Sync** expansion modules.
   - *Note on `v3ntus` blog post:* The community blog post noticed the string `10M04SC` and assumed an Intel MAX 10 was on the Ninja V mainboard; `MANIFEST.XMD` and `XMODSDI.BIN`/`XMODSYN.BIN` prove that `10M04SC` is actually inside the **AtomX SDI (`id=0`)** and **AtomX Sync (`id=1`)** expansion modules, programmed over JTAG by the Ninja V when an expansion module is attached!

## 2. ZynqMP `XCZU5EV` Programmable Logic Bitstreams (`DPGA00XX.BIN` & `emergency.bit`)

Every `DPGA00XX.BIN` file in `fat16_fs/` is exactly `7,797,692` bytes (`0x0076FBBC`) and contains a ZynqMP Boot Header (`XLNX`), an Image Header containing the original `.bit` filename, a Partition Header (`attr = 0x000000A0` -> Destination PL + AES-GCM Encrypted), and `7,792,256` bytes (`0x0076E680`) of AES-GCM-256 encrypted bitstream payload + authentication tag.

At runtime, the active FPGA bitstream exposes its type identifier at physical AXI-Lite register **`0x820010DC`** (verified via `/etc/init.d/load_fpga.sh` and `/usr/bin/load_fpga`).

## 3. Expansion Module FPGAs & `MANIFEST.XMD` Mapping

The file `fat16_fs/MANIFEST.XMD` (`172` bytes) defines the exact hardware mapping for external AtomX expansion modules attached to the Ninja V's AtomX expansion port:

```text
0,XMODSDI.BIN,
1,XMODSYN.BIN,
2,XMODDOCK.BIN,FMODDOCK.BIN,DOCKUSB.BIN
4,XMODSDIN.BIN,
5,XMODSYNN.BIN,
6,XMODSTRM.BIN,FMODSTRM.BIN,
```
